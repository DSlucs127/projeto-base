# 05-i18n

Padrao de internacionalizacao. **Obrigatorio**: pt-BR + en.

## 1. Android

Resources em duas pastas:

```
app/src/main/res/
├── values/strings.xml         (padrao: pt-BR)
└── values-en/strings.xml      (ingles)
```

Exemplo `values/strings.xml`:

```xml
<resources>
  <string name="app_name">Projeto</string>
  <string name="auth_login_title">Entrar</string>
  <string name="auth_error_invalid">Credenciais invalidas.</string>
</resources>
```

Exemplo `values-en/strings.xml`:

```xml
<resources>
  <string name="app_name">Project</string>
  <string name="auth_login_title">Sign in</string>
  <string name="auth_error_invalid">Invalid credentials.</string>
</resources>
```

Uso:

```kotlin
import app.core.i18n.t

textView.text = t(R.string.auth_error_invalid)
```

`t()` resolve o locale ativo; se string nao existir em `values-en/`, cai no padrao.

## 2. Cloud Functions

Mensagens de erro i18n:

```ts
import { tr } from './translate';

throw new HttpsError('unauthenticated', tr(req, 'auth.error.invalid'));
```

`tr()` aceita `req.data.lang` ou o header `Accept-Language`.

## 3. Catalogo canonico

Todas as chaves existem tambem em [`shared/I18N-KEYS.json`](../../../shared/I18N-KEYS.json). O validator `tools/scripts/check-i18n.ts` compara `strings.xml` pt-BR e en com o catalogo e bloqueia PR com chave faltando, chave extra em so um locale ou valor divergente do catalogo.

Resource names do Android nao aceitam pontos: a conversao canonica e `.` -> `_` (`auth.login.title` -> `auth_login_title`; `errors.404` -> `errors_404`).

## 4. Novos plugins

Plugins podem trazer `locales/pt-BR.json` e `en.json`. No build Functions,
esses dicionarios sao registrados pelo `pluginsRegistry` quando o registrar do
plugin e empacotado. Este scaffold nao faz merge de recursos Android em runtime;
a aplicacao hospedeira integra recursos de UI ao adicionar o plugin.

## 5. Regras

- Nada de string literal em codigo: sempre `R.string.<x>` ou `tr('x')`.
- Nada de `Locale.US` hardcoded - usar `Locale.getDefault()`.
- Toda nova chave precisa estar no catalogo canonico + `strings.xml` (pt-BR + en).
